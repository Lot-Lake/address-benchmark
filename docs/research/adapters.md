# Adapter readiness and attribution inventory

Research date: **2026-11-01**. This is an integration inventory, not an accuracy ranking or an endorsement of upstream performance claims. Only the authored examples and optional usaddress wrapper are in the initial implementation. No external parser source, trained model, third-party corpus, or private address extract is bundled. Installed runtime verification is a separate step from documentation research.

## Readiness gates for a real plugin

1. **Pin the exact implementation.** Package artifact hash or source revision, model hashes, lockfiles, build flags, runtime/compiler, optional feature flags, and effective thread counts. Record runtime discovery failure explicitly.
2. **Declare evidence capabilities.** Native roles, ordered/repeated components, native versus adapter-derived spans, unsupported roles, and any information lost in the upstream public interface. Gold must never be available to the adapter.
3. **Version the mapping.** Coarse `road` is a valid coarse observation; it is not a fine token decomposition. Keep null/unmapped roles in audit output. Publish lossy mappings, and do not score an unsupported output as if it had the same annotation granularity.
4. **Separate task boundaries.** Parsing, text normalization, field formatting, inferred locality/state, geocoding, verification, matching, and search require different references and metrics. A helpful inferred value is not source evidence.
5. **Conform before timing.** Use authored examples for leading-zero ZIPs, punctuation, UTF-8, repeated/nonadjacent roles, incomplete addresses, errors/refusals, and locale mismatches. Assert that outputs preserve native tokens and that adapters receive only input/configuration. Alignment must never be gold-assisted.
6. **Audit assets independently.** Corpus manifests require provenance/revision/hash/license, construction history, task/locale, complete/partial annotation declarations, source-family IDs, split/exposure history, and exact-overlap policy. If rights are unestablished, provide a private local plugin recipe and no raw downloadable asset.

## Avoiding false independence

usaddress, fastaddress, and polars-usaddress share a model lineage according to their upstream descriptions. Their implementation differences are valuable to measure, but agreement among them does not supply three independent reference annotations. Likewise, default and Senzing libpostal models need separate identity but do not turn overlapping evaluation corpora into independent experiments. No gold-selected union of predictions is an attainable single-engine result without a separately evaluated selector.

## Corpus publication posture

Doorplate's public code, public repository fixtures, GeoSearch views, generated source-field supervision, and naturally typed addresses must each be reviewed at the asset level. Do not infer that a repository's wrapper license covers every source row. This MVP uses newly authored fictional examples, with explicit construction and redistribution statements, so its CI can run without an external account, network, model, or data cache. Such a small authored corpus tests the protocol and scorer; it cannot establish population accuracy.

The previous project's private `public-listing_placekey.csv.zip` has no established redistribution license. It and all raw extracts remain excluded. Its unlabeled listing stress sample can establish workload behavior only, not parsing accuracy. Existing corpus sizes are historical context and are not bundled distributable assets.
